# Устройство

Как устроены сервер, бот, Mini App, PWA и приложение «Капибары»: расписание, СДО, файлы и поиск, ИИ, уведомления, группы, вход, приватность и оплата.

Модули названы по-старому; где каждый сейчас — таблица `MOVED` в `tests/test_moved_modules.py`. Код сервера лежит в пакете `kapibara/`, в корне только `bot.py`. Переменные окружения — в [configuration.md](configuration.md), архитектурные решения — в `docs/adr/`.

## Расписание

Официальный API `schedule-of.mirea.ru` из-за рубежа не отвечает, поэтому используется зеркало `english.mirea.ru/schedule/api/ical/{тип}/{id}`. Типы: 1 — группа, 2 — преподаватель, 3 — аудитория.

- Поиска на зеркале нет. `schedule_index.py` один раз обходит id, берёт имена из `X-WR-CALNAME` (первый килобайт, заголовок Range), хранит их в SQLite и обновляет раз в месяц. Поэтому поиск работает и через прокси.
- `schedule_parser.py` — загрузка расписания группы с кэшем и запасной копией, готовые ответы. Снаружи импорт идёт из `schedule_parser`.
- `schedule_events.py` — разбор ical: `lessons_for_date`, `week_overview`, `target_weeks`, номер недели из событий «N неделя».
- `schedule_format.py` — оформление ответов.
- Чужие календари МИРЭА кэшируются на 10 минут (`mirea_schedule_api.fetch_ical`). Календарь группы загружается одним запросом на всех, битый ответ не затирает копию.
- Inline-режим (`handlers/inline.py`, включается через `/setinline` в BotFather) отдаёт картинки расписания `schedule_card.py` (Pillow, всегда тёмные) по подписанной ссылке `/card/<ключ>.jpg?sig=` с сервера WebApp. Без `WEBAPP_URL` ответ идёт текстом.

Предметы по выбору (`OPTIONAL_SUBJECTS`, `optional_subjects.py`, команда `/optional`): пары скрыты, пока человек не ответит «хожу».

## СДО (Moodle)

СДО — `online-edu.mirea.ru`. Доступ идёт по куке `MoodleSession`. Из облачной среды разработки СДО недоступен, с сервера бота доступен; зарубежные серверы СДО не пускает.

Клиенты к СДО создаются только через `sdo_net.client(cookie)`. В нём есть предохранитель: если три раза подряд не удалось соединиться за 10 секунд, следующую минуту запросы сразу возвращают ошибку, а не ждут по 30 секунд.

Сессия Moodle гаснет меньше чем за 6 часов без запросов, поэтому её держит проверка куки раз в 55 минут (`scheduler.sdo_keepalive`). Реже проверять нельзя. Без сбоев кука живёт сколько угодно; гибнет от «Выйти» в браузере, смены пароля или перезапуска СДО.

### Дедлайны

Модуль `sdo_parser.py`.

- Основной источник — AJAX `core_calendar_get_calendar_monthly_view` на 5 месяцев (sesskey берётся со страницы `/my/`). Запасной путь — «Предстоящие события».
- Типы сроков перечислены в `DEADLINE_EVENTS`.
- Курсы не этого семестра отсекаются по метке вида `[II.25-26]` в названии и по отсутствию в расписании группы (`not_this_semester`). Исключения — `KEEP_COURSES` (переменная `SDO_KEEP_COURSES`, по умолчанию «Учебный отдел»).
- Ручная правка дедлайна (`manual_edit`) защищает его от перезаписи синком.
- Общий дедлайн каждый может изменить или убрать только у себя: `deadline_mine` хранится поверх общих полей, в API это `scope: me|all`. Староста группы меняет для всех.
- Если дедлайн пропал из полного календаря СДО два синка подряд, он убирается (`sdo_parser.drop_vanished`, у группы свой счёт). Удалённый дедлайн попадает в `deadlines_skipped`, синк его не вернёт.
- Название приводит `deadline_names.pretty` после проверки семестра: «Практика 2 · Анализ данных (Экз)». `course_of` понимает и этот формат.
- Личный дедлайн старосты, созданный из WebApp, — `deadlines.personal`.

### Файлы

Модуль `sdo_files.py`, команда `/sdofiles`.

- Курсы берутся через AJAX «Мои курсы», материалы — со страницы `course/resources.php`, папки раскрываются.
- Сначала идёт пробный прогон, потом выгрузка кнопкой: файл отправляется старосте, бот берёт `file_id` и удаляет сообщение.
- `files.source` защищает от дублей, `files_skipped` — удалённое не возвращается.

### Вход студента и сдача работ

Во вкладке «СДО» WebApp (кнопка «Вход») студент вставляет свою `MoodleSession`. Код — `sdo_accounts.py`, таблица `sdo_sessions`, шифрование Fernet. У старосты без своей сессии используется общая из `SDO_SESSION_COOKIE`. Проверка входов идёт вразнобой (`keepalive_due`): первые три раза через 50–59 минут случайно, потом раз в 55 минут.

Сдача — кнопка «Сдать» у дедлайна-задания (`mod/assign`), модуль `sdo_submit.py`:

1. форма editsubmission;
2. `repository_ajax.php`;
3. savesubmission;
4. при черновиках — confirmsubmit.

Что принимает задание (типы вроде «только .zip», число файлов, размер), берётся с той же формы (`accepted_types`, `/api/sdo/submit-rules`). Лист «Сдать» показывает это до выбора файлов и отсекает чужой тип. За один раз можно сдать до 3 файлов (`sdo_submit.MAX_FILES`, плюс `maxfiles` задания).

Если задание сдано через бота или в журнале оно зачтено или ждёт оценки, дедлайн отмечается сданным сам (`sdo_done.py`). Отметку бот не снимает.

Протухший вход приложение на телефоне обновляет само (`app/lib/screens/sdo_relogin.dart`): невидимое окно СДО, единый вход МИРЭА ещё помнит пользователя, новая сессия приходит на `/sdo/connect` с `via=silent`. Если спросили пароль, обновление не удалось. Работает только после входа страницей на этом телефоне, раз в 30 минут. «Отключить» и выход стирают куки окна. Способ входа хранится в `sdo_sessions.via`.

### Баллы БРС

Модули `sdo_grades.py`, `js/sdo.js`.

- Журнал курса `/grade/report/user/index.php?id=<курс>` читается входом студента. Из него получаются категории, сумма и работы текущего контроля. Работа зачтена, если балл не ниже проходного (нужно не меньше 75 %). Страницы заданий дают порог, статус и срок. Кэш — 10 минут.
- Экран задания (`parse_task_page`, `/api/sdo/task/<cmid>`): описание, файлы преподавателя через подписанные `/sdl/…` (качаются входом студента), сдача.
- Новые баллы — `grade_alerts.py`. Проверка идёт у каждого вместе с проверкой его входа в СДО, раз в 50–59 минут вразнобой, днём с 8 до 23 (`check_soon`). Баллы сверяются с историей `sdo_history`; в уведомлениях есть тумблер `grades`. Точка истории пишется всем с рабочим входом, сообщение приходит только при включённом тумблере.

### Посещения лекций

Модуль `attendance.py`, экран «Посещения» открывается из строки «Посещаемость». Пульс МИРЭА сервер не пускает, поэтому посещения восстанавливаются из баллов СДО.

- Баллы начисляются только за лекции (практики не в счёт) и делятся поровну на лекции семестра из расписания. Отметка «У» выбывает из деления. `solve` находит число посещённых лекций и «ушек».
- Какие именно лекции посещены, определяется по приросту в `sdo_attendance_history` (одна точка в день). До начала истории человек отмечает сам, не больше, чем следует из баллов (`attendance_marks`, `/api/sdo/attendance/{курс}`).
- Пульс МИРЭА (посещения по датам) закрыт DDoS-Guard. Доступность проверяет `/pulsecheck`. Разведка схем — `/pulseprobe` (`pulse_probe.py`): файлы приложения и, при заданном `PULSE_COOKIE`, свои ответы gRPC-Web по номерам полей. Только чтение, только свои данные.

### Цель по предмету

Модуль `sdo_goal.py`, карточка «Цель» на экране предмета.

- Своя оценка хранится в settings под ключом `goals:<id>`; без неё берётся первая отметка курса.
- Считается, сколько баллов не хватает, какие работы открыты, сколько посещений впереди. Действует правило 75 %; работы со статусами `low` и `miss` не учитываются, потому что пересдачу открывает преподаватель.
- Итог — одно из `done`, `ok`, `tight`, `no`. Есть расчёт «что если пропущу лекцию».
- Дат и раскладки по времени нет намеренно: работы делаются в любом порядке, автопилот с датами не делается.

## Файлы и конспекты

- Тип файла определяет `file_categories.py` по названию: лекции, практики и лабы, КР и тесты, методички, экзамен, другое. Номера сортируются естественным образом.
- Удалять файлы может только староста (`/delfile`, кнопки в WebApp).
- Файл по просьбе в чате («скинь практику 3 по основам предпр деят») отдаёт `file_request.py`, это происходит до обращения к ИИ.
- В WebApp кнопка «Скачать» использует `Telegram.WebApp.downloadFile` по подписанной ссылке `/dl/…` (до 20 МБ), «В чат» — бот присылает файл в личные сообщения.
- Конспект лекции: `lecture_summary.py`, `/api/summary/<id>`, таблица `file_summaries`. Нажатие на файл с текстом открывает лист «Конспект». Конспект создаётся только по кнопке, один на файл и общий для всех, ИИ вызывается один раз. Одинаковая лекция в разных файлах получает один конспект (`file_text.text_hash`, `get_file_summary`).
- Понятные названия: `file_names.py`, команда `/tidyfiles` у старосты (показывает «было → стало», отдаёт полный список файлом, есть кнопка применения и `/tidyfiles undo`). Старое имя хранится в `files.orig_title`.
  - Лекциям без темы тема берётся из начала текста (`lecture_topic.py`, `file_names.text_titles`; в превью помечено значком, есть кнопка «Без …»).
  - PDF и презентация одной лекции получают одно название, без «(PDF)».
  - В приложении и WebApp тема выводится строкой под «Лекция N» (`head` и `topic` в `/api/files`, `file_names.split_title`).
  - Названия дедлайнов СДО приводятся при синке в `deadline_names.py`, отдельной команды нет.
- Файл, загруженный человеком, попадает в его группу (`add_file`, `current_group`).

## Поиск по лекциям

Модули `semantic_index.py` и `semantic_search.py`.

- Лекции режутся на куски: страницы PDF, слайды PPTX, части DOCX и TXT (`chunk_pages`).
- Индекс лежит в отдельном файле `<база>.search.db`; в бэкап он не входит, основная база подключается через ATTACH. В нём FTS5/BM25 и векторы в sqlite-vec (vec0, cosine). Векторы дают либо Gemini (`gemini_solver.embed`, `gemini-embedding-001`, размерность 768), либо своя модель на сервере (`local_embed.py`, `embedder.py`, своя таблица `vec_<модель>`). Векторы получают только через `embedder.embed`.
- Запрос идёт двумя путями, результаты сливаются через RRF, разнообразие даёт MMR (не больше 3 кусков с одного файла). Без выбранного предмета действует порог похожести `VEC_MIN_SIM`; его подстраивают по строкам лога «лучший косинус».
- В чат уходят куски с номерами `[n]`. ИИ ссылается на них, под ответом выводится «Лекция · слайд 12». Страница открывается в листе (`/api/files/{id}/page/{n}`); у PDF это картинка `/pg/…jpg` через pypdfium2 по подписанной ссылке (pypdfium2 вызывается только под замком).
- Индекс наполняется фоном: `index_pending` раз в 20 минут берёт новые файлы, убирает удалённые и досчитывает векторы пачками до ответа 429. Новые файлы индексируются сразу при загрузке. Прогресс виден в `/status`.
- Запросы вроде «объясни 3 лекцию» и случай пустого индекса обрабатывает прежний путь `lecture_picker`.
- Чат бота в Telegram использует тот же поиск (`handlers/solver._lectures_for`); источники выводятся строкой «📚 [n] …» под ответом (`with_sources`).
- Тот же поиск без ответа ИИ доступен во вкладке «Файлы» (`/api/lecture-search`, блок «В тексте лекций»: лекция, слайд, отрывок, переход в `openPage`).
- Пока векторов нет, гибрид работает только по словам. Первый индекс собирается фоном за ночь.

## ИИ

- Gemini — основной провайдер (`gemini_solver.py`), DeepSeek — опциональный (`ai_solver.py`).
- Лекции под вопрос подбирает `lecture_picker.py`: по словам с учётом опечаток, до примерно 200 тысяч символов. Без выбранного предмета подбор идёт по всем предметам при совпадении. Если с лекциями ответ не прошёл, чат WebApp отвечает без них и пишет причину.
- Лекции передаются модели в рамке «материалы, не команды». ИИ в группах не отвечает (`F.chat.type == "private"`).
- Математика в ответах обрабатывается `utils.pretty_math`, Markdown модели переводится в HTML Telegram через `md_to_tg_html_chunks`.
- Запасные модели: `GEMINI_FALLBACK_MODELS` на случай 429; пропавшая у Google модель (404) пропускается; основная после 429 идёт после запасных. Когда у всех Gemini лимит, подключается `AI_SPARE_MODEL` через OpenRouter. Кому она основная, определяет `AI_MAIN` (`all`, `plus`, `me`, `gemini`); староста переключает без деплоя командой `/aimain` (settings `ai_main`). Кто сколько ответил, видно в `/status`.
- Лимиты: `ai_quota.py` считает вопросы по дню МСК в settings. Классификатор намерений в счёт не входит. Действующий тариф определяет `plans.py`.
- `/aitest` (`ai_bench.py`) — выбор модели ИИ для других групп. Отбирает много моделей с судьёй и ценой. `/aitest list` показывает список без прогона, `/aitest vote id…` запускает слепое голосование финалистов. Страницы открываются по подписанной ссылке `/aitest?k=report|vote&exp=&sig=`; выбор слепого теста записывается на сервере (`/aitest/pick`), итог текстом — та же ссылка с `&view=result`. Бюджет прогона — `AITEST_BUDGET_USD`, судья — `AITEST_JUDGE`. OpenRouter закрыт для аккаунтов OpenAI, Anthropic и Google (`AITEST_SKIP_VENDORS`); текущая Gemini проверяется своим ключом (`gemini-direct`).
- «Подумать ещё» (`think.py`): подписчикам под ответом доступна кнопка, которая решает тот же вопрос моделью `AI_THINK_MODEL`. Это платная модель через OpenRouter с `data_collection: deny` (не `:free`, из-за 152-ФЗ). На время запроса включается `gemini_solver.forced_model`, запасные модели не используются. Лимит — `AI_THINK_DAILY` (10) на человека и `AI_THINK_DAY_USD` на всех. Сбой не списывается. На iPhone и для фото и файлов функции нет. Выключается `/aithink off`, траты видны в `/status`.
- ИИ-чат демо-входа использует настоящую модель по демо-данным (`demo_chat` → `webapp/routes/chat.reply`, лекции из `site/demo_lectures.json`), без базы и лимитов людей; предел — 40 вопросов в сутки.

## WebApp и API

Mini App работает внутри процесса бота (FastAPI и uvicorn, `webapp/server.py`, запуск — `bot.start_webapp`). Авторизация — по `initData` (HMAC, `webapp/auth.py`).

Бэкенд:

- `webapp/server.py` — только каркас: CORS, заголовки, `/health`, index, статика последней.
- `webapp/deps.py` — `CurrentUser`, `tg_bot()`, `BOT_TOKEN` и `WEBAPP_URL`. Читать их нужно как `deps.X`; тесты подменяют значения именно там.
- Обработчики — `webapp/routes/{schedule,deadlines,files,chat,sdo,account}.py`. Новый модуль добавляется в цикл `include_router` в `server.py`.
- `/` отдаёт index со ссылками `?v=<хэш>` против кэша Telegram.

Фронт: `webapp/static/index.html`, `app.css` и `js/{core,icons,home,deadlines,files,search,chat,more,sdo,main}.js`. Это классические скрипты с общей глобальной областью, порядок подключения важен. Иконки свои (`js/icons.js`: спрайт, `icon("имя")`, `fileTypeIcon`), эмодзи в интерфейсе не используются. Ответы старых запросов сверяются с открытым экраном по номеру запроса. Блок «Что нового» после обновления — `NEWS` в `js/more.js` (`id` меняется на каждый выпуск).

API как контракт:

- `/api/v1/…` равен `/api/…` (`server.ApiV1`). Своё приложение и PWA работают на v1.
- `/api/meta` отдаёт версию сервера и минимальные версии приложения (`APP_MIN_WEB`, `APP_MIN_ANDROID`, `APP_MIN_IOS`), а также `build` (короткий хеш, номер последнего PR, время сборки и запуска; пишет `deploy/timeweb/update.sh` в `build-info.json`).
- Снимок путей — `tests/api_contract.json`. Убранный путь делает CI красным; при добавлении нужно выполнить `python tools/api_snapshot.py`.
- Правила для API: JSON без HTML, группа берётся из профиля, а не из config, рассылки идут через слой доставки.

### Дизайн-токены

`design/tokens.json` хранит темы («Глубина», «Тетрадь», «Ночная тетрадь»), цвета предметов, шрифты («Книжный», «Строгий»), размеры, радиусы, отступы, движение и вибрацию. `python tools/tokens.py` собирает `webapp/static/tokens.css` (тест следит за актуальностью) и Dart-константы для `app/`. Правила бренда — `docs/brandbook.md`.

## PWA

`/app` — приложение вне Telegram. Реализаций две; по умолчанию отдаётся версия на HTML (`PWA_DEFAULT = "html"` в `webapp/server.py`), переключатель — переменная `PWA_ENGINE=html|flutter`.

- Общее для обеих: `manifest.webmanifest` (`start_url` — `/app`, иконки в `static/pwa/`), `sw.js` (регистрируется только вне Telegram: оболочка из кэша, GET `/api/…` — сеть до 5 с, иначе последний ответ; выход чистит данные), системная тема вне Telegram (`core.js`). Вне Telegram скачивание идёт обычной ссылкой, «Ярлык» — установка браузера (Android) или подсказка «Поделиться → На экран „Домой“» (iPhone).
- PWA на HTML (`webapp/static/app-html`) — всё приложение страницей, один к одному с приложением на iPhone (оплата — как в вебе).
  - `js/core.js`: `Prefs` (ключи shared_preferences `flutter.<имя>`), `Api`, `Theme`, `Nav`, `Sheet`, уведомления с выглядывающей капибарой.
  - `shell.js`: вкладки и `afterStart` (согласие, группа, тур).
  - `capy_scenes.js`: капибара-загрузка `spinner()`, `pullRefresh`.
  - Экраны — `js/screens/*.js`, по файлу на экран Flutter, связь через `window.openX`. Стили — `css/app.css` и `css/<экран>.css`.

Собирает её `tools/pwa_build.sh` (`--base-href /app/`, canvaskit своим сервером), коммитит GitHub Actions `app-web.yml` после мержа изменений в `app/`; руками сборку не правят. ## Доставка уведомлений и пуши

Все рассылки (утро, пары, дедлайны, новые задания, обзор недели, новые баллы) идут через `delivery.deliver(bot, uid, html, kind=, tab=)`: Telegram плюс веб-пуш на устройства, где включены уведомления (`push_subs`, `/api/push/*`, тумблер в «Уведомлениях» PWA).

- Веб-пуши — `webpush.py` без внешних библиотек: RFC 8291 aes128gcm и VAPID на `cryptography`. Ключ VAPID — `VAPID_PRIVATE_KEY` или производный от `BOT_TOKEN`.
- Пуши своего приложения — `app_push.py`. Телефон даёт ключ AES-256 при включении (`/api/push/app/subscribe`), сервер шифрует заголовок и текст, FCM, RuStore и APNs видят только шифротекст. Ключ хранится в базе (`app_push`) в зашифрованном виде, как входы СДО. Android принимает и расшифровывает на Kotlin (`app/android/.../push/`, RuStore — при сборке с `RUSTORE_PROJECT_ID`), iPhone — расширением `KapibaraNotify` (подключение описано в `docs/app-push.md`). Без переменных канал выключен.
- Планировщик — `scheduler.py` (APScheduler): утро и напоминания; обзор недели в воскресенье в 19:00 — `weekly_digest.py`; свои напоминания о дедлайнах — `deadline_reminders.py`; история баллов — `sdo_history.py`.
- Рассылки идут по календарю группы каждого получателя (`scheduler._group_raws`: календарь каждой группы загружается один раз на рассылку). Между сообщениями пауза `scheduler.pace()` (`PACE_SECONDS`, лимит Telegram около 30 сообщений в секунду).
- Настройки уведомлений — `notify_prefs.py`, WebApp «Ещё → Уведомления», `/api/notify`: JSON в `users.notify` поверх `DEFAULTS`. Настраиваются что слать и в какие дни, погода, «другой корпус» (корпус — в скобках в LOCATION, свой — самый частый), «только если есть пары», напоминание перед парой по сценарию (`REMIND`: первая пара, после короткой перемены, после большого перерыва; `plan_reminders`). Общий выключатель — `users.subscribed`.
- Новые задания из СДО — `new_tasks.py`: после синка каждому со включённым `new_tasks`, только видимые ему и не сданные. Если за синк больше 8, это считается выгрузкой и уведомление не отправляется.
- Длинные сообщения режутся на части (`long_messages.py`, middleware сессии бота).

## Группы

Любая группа института может пользоваться ботом.

- Группа человека — `users.group_id` (id группы на зеркале расписания; справочник — `schedule_index`). Своя группа — `config.HOME_GROUP_ID` из `ICAL_URL`. Новые пользователи выбирают группу при `/start` или в листе «Из какой ты группы?» WebApp; сменить можно через `/group` и «Ещё → Группа» (`groups.py`, `handlers/group_pick.py`, `/api/me`, `/api/groups/search`, `/api/me/group`).
- Тариф определяет `plans.py`: `own` — своя группа и старосты, `sub` — подписка (`subscriptions`, `/sub <id> <дней>`), `base` — остальные. От тарифа зависит только ИИ: `ai_quota` (проба `AI_TRIAL_DAILY` и `AI_TRIAL_DAY_TOTAL`, конспекты `SUMMARY_WEEKLY` в неделю, подписка `AI_SUB_DAILY`).
- Данные по группам:
  - расписание — `schedule_parser.raw_for_user` и `fetch_schedule_raw(group_id=…)` (чужая группа — через `mirea_schedule_api.fetch_ical`);
  - общие дедлайны, ДЗ, заметки и файлы хранятся с колонкой `group_id` (NULL — своя группа);
  - видимость — `database/groups.py` (`scope_sql`, `file_scope_sql`, `file_groups`: файл может быть общим с группой);
  - группа запроса — `database.groups.current_group` (ContextVar: в WebApp её ставит `get_current_user`, в боте — `GroupContextMiddleware`). Функции базы без явного `group_id` берут её; рассылки и синк работают со своей группой;
  - строка базы с `group_id` NULL — своя группа (`database.groups.row_group`), а не группа запроса.
- Старосты групп — таблица `group_admins`, проверка `is_editor(uid, group_id)`. Стать старостой можно через `/iamstarosta` или кнопку «Я староста этой группы» в листе группы; администратору приходит «Одобрить / Отклонить».
- Своя группа — участники чата группы в Telegram (`members.py`). Чат — `GROUP_CHAT_ID` или запомненный, когда староста добавил бота в чат (`handlers/members_chat.py`). Только участники выбирают свою группу, видят её данные и получают тариф `own` (даже выбрав другую группу). Ответ getChatMember помнится 12 часов (`member:<id>` в settings). Если чат не задан или Telegram молчит, работает прежнее поведение.
- СДО других групп — `group_sync.py`: задания группы берутся по входу человека, который согласился делиться (`sdo_sessions.share`, тумблер в листе СДО, `/api/sdo/share`). Используются `sdo_parser.apply_items(items, group_id)`, external_id `sdo:<группа>:<id>`, период — `SDO_SYNC_INTERVAL_HOURS`.

## Вход без Telegram

### Вход через бота

`/api/auth/start` возвращает код и ссылку `t.me/<бот>?start=login_<код>`. В боте появляется запрос «Войти на Chrome · Android? Да, это я» (`handlers/start.ask_login`) с числом с экрана устройства из трёх вариантов (как у Google). `/api/auth/poll` выдаёт токен сессии устройства (`database/sessions.py`; в базе только хэш, срок 90 дней с продлением).

Запросы идут с `Authorization: Bearer` (`webapp/deps._session_user`). Фронт хранит токен в localStorage (`core.js`: `APP_TOKEN`, экран «Войти» — `showLogin`). Устройства и «выйти везде» — в листе «Безопасность».

### VK ID и Яндекс ID

Модули `oauth.py`, `database/identities.py`.

- Цепочка: `/api/auth/<vk|yandex>/start` → провайдер → `/callback`. Токен получает только тот, кто вошёл: PWA — через `/app#token=…`, приложение — через `ru.uiboshki.app://auth#code=…` с одноразовым кодом, который меняется на токен по `/api/auth/exchange` (PKCE, секрет приложения; старые версии принимают `#token=`). Опрос по коду, как у бота, здесь невозможен: чужую ссылку можно подсунуть.
- Привязка к аккаунту — `/link` и страница «Да, привязать» с именем аккаунта.
- Без привязки создаётся новый аккаунт без Telegram: номер не больше `LOCAL_BASE` (`is_local`), рассылки только пушем (`delivery.deliver`), «В Telegram» недоступно.
- Нужны `VK_CLIENT_ID` (и `VK_CLIENT_SECRET`), `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`; без ключей кнопок нет. Адреса возврата у провайдеров: `https://www.uiboshki.ru/api/auth/<vk|yandex>/callback`.
- Вход по SMS не делается (платно, накрутка SMS). Корень `/` вне Telegram без токена отдаёт сайт.

### Вход через Apple

В iPhone-приложении: `apple_signin.py`, `POST /api/auth/apple`. Нужны ключи `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` (.p8), `APPLE_CLIENT_ID` (по умолчанию `ru.uiboshki.app`); без них кнопки нет. Удаление аккаунта и отвязка отзывают вход у Apple (`apple_tokens`). Право `com.apple.developer.applesignin` в `Runner.entitlements` добавляется только вместе с подписью для App Store (AltStore с ним приложение не ставит).

### Демо-вход для проверяющих

`REVIEW_CODE` (от 12 знаков) включает «Вход по коду доступа» в приложении для проверяющих App Store и RuStore. Ответы берутся из `site/demo.json` со сдвигом на текущую неделю (`review_demo.py`, токен `rv.…`). Без переменной кнопки нет.

### Подписка на канал при входе

`login_channel.py`: новый человек при первом входе через Telegram подписывается на открытый канал (`LOGIN_CHANNEL`) до вопроса «это вы?». Бот должен быть администратором канала. В приложении из стора кнопка идёт с вариантом «Позже». Если переменная пуста, проверки нет. Строка «Новости Капибары — @канал» выводится в `/start`, `/help`, `/app` и описании бота (`login_channel.news_line`).

## Приватность (152-ФЗ)

Модуль `privacy.py`.

- Согласие даётся галочкой (по умолчанию не стоит): «Даю [согласие на обработку персональных данных]» и «Подробнее — в [Политике…]» синими ссылками; кнопка неактивна без галочки. Так сделаны все галочки.
- Тексты — `legal_texts.py`, одни для `/consent`, `/privacy` и `/api/legal/<имя>`. Лист показывается в Mini App и PWA (`js/privacy.js`) и в приложении (`screens/legal.dart`), каждый в своём дизайне. Длинный раздел имеет `short`: главное коротко, полный текст по «Подробнее». В текстах называются компании, а не модели ИИ.
- При смысловой правке текста поднимается `privacy.VERSION`, и всех спрашивают заново. Тексты о сервере и бэкапе (копии не дольше 30 дней, ст. 21 ч. 5) и о том, как запросы уходят за границу, собираются по переменным (`privacy.backup_texts`). Хостинг в политике называется по `HOSTING` (`privacy.HOSTS`).
- Согласия хранятся в `consents`; бот спрашивает через `ConsentMiddleware`. Без согласия (`privacy.blocked`, касается только новых пользователей) бот отвечает только сообщением согласия; допустимы `/privacy`, `/deleteme` и вход `login_`. API отвечает 403, кроме `/api/me`, `/api/consent`, `/api/me/delete` (`webapp/deps.CONSENT_FREE`). События, имя и рассылки при этом не собираются.
- Пользователи, существовавшие до согласий, помечены `users.legacy`. Их и тех, кто дал прошлую версию, спрашивают один раз на версию текста (`privacy.ask_once`, отметка `users.consent_asked`, лист — `POST /api/consent/asked`); блокировки нет (`has_any_consent`).
- Оператор в текстах задаётся переменными `PD_FIO`, `PD_INN`, `PD_EMAIL`, `PD_CITY`.
- Удаление данных (`privacy.erase`: все таблицы с `user_id` из схемы, тест `test_privacy.py`). Пользователь вписывает фразу `privacy.ERASE_PHRASE` руками. Сразу удаляются согласия, входы и СДО, обработка встаёт (`blocked`, таблица `erase_requests`). Полное удаление — через `ERASE_DAYS` = 7 дней (`privacy.purge`). До истечения срока вернуть данные может староста командой `/undelete <id>` по заявке, без гарантии.
- В эти 7 дней человек исключается из рассылок, `/stats`, рейтингов, списка участников группы и «показывать меня всем». Выборки по людям используют `database.privacy.NOT_ERASING` (или `NOT_ERASING_FOR("u.user_id")`), по одному человеку — `privacy.blocked`.
- Новая колонка «кто создал» в общей таблице дописывается в `database/privacy.AUTHOR_COLUMNS`.
- Срок хранения — год без заходов (`last_seen`). События (`events`) старше 180 дней удаляются.
- Секретный ключ входов студентов в СДО (`SDO_CRYPT_KEY` или `SDO_CRYPT_PASSPHRASE`) шифрует их (Fernet). При смене ключа при запуске все входы перешифровываются (`sdo_accounts.rotate_all`), старые ключи остаются запасными.
- Ночная копия базы шифруется (`BACKUP_KEY`, AES-256-GCM, файл `.db.gz.enc`); расшифровать без бота — `tools/backup_decrypt.py`. Автор «Подслушано» хранится как хэш и через сутки затирается.

## Записи пользователей и жалобы

Модуль `ugc.py`.

- Жалоба на заметку, ДЗ, файл или общий срок приходит администратору в бота с кнопками «Удалить / Оставить» (`handlers/reports.py`).
- Автор удалённого получает «Оспорить»: бот просит написать, с чем он не согласен (`reports.appeal`, 10–500 знаков, отмена). Администратору приходит текст и кнопки «Вернуть / Оставить скрытым». Копия удалённого хранится 30 дней (`reports.snapshot`).
- Для заметок действует антиспам `ugc.note_spam`.
- «Скрыть автора» работает у самого пользователя (`user_blocks`). Любой новый список записей людей в API нужно фильтровать через `ugc.without_hidden`.
- Правила сообщества — `legal_texts.RULES` (`/rules`).
- Расписание без входа доступно через `/api/guest/…` и `app/lib/api/guest.dart`.

## Комментарии и оценки преподавателей

- Комментарии под парой — `lesson_comments.py`, таблица `lesson_comments`, `/api/lesson/comments`. Ключ пары такой же, как у реакций. Комментарии видит своя группа. Писать можно за неделю до пары и две недели после. Мат отсекает `nick_filter.rude`. Жалоба и «скрыть автора» — вид `comment` в `ugc.py`; удалить может автор или староста.
- Оценка преподавателя — `teacher_rating.py`, таблица `teacher_ratings`, `/api/teacher/rating`. Оценка от 1 до 5 капибар, только цифра. Ставить можно, если преподаватель есть в календаре своей группы. Среднее показывается от `SHOW_MIN` = 3 оценок. Иконки капибар — `app/assets/rating/` и `webapp/static/img/rating/` (силуэты-маски, цвет даёт тема).
- Вид: на экране пары под именем преподавателя ряд капибар и лист оценки (`widgets/teacher_rating.dart`). Под реакциями блок «Обсуждение группы» с двумя последними сообщениями и кнопкой «Всё обсуждение · N». Всё обсуждение и поле ввода открываются листом (`widgets/lesson_comments.dart`); долгое нажатие на чужое сообщение — жалоба или скрыть, на своё — удалить. В чужом расписании (поиск) этого нет.
- Политику и согласие под эти функции (`privacy.VERSION`) поднимают вместе с релизом в магазины.

## «Капибара+» и оплата

Модули `billing.py`, `referrals.py`, `webapp/routes/billing.py`, `handlers/plus.py`.

- Оплата только на сайте `/plus` по личной ссылке; в Telegram это кнопка-ссылка (цифровые товары в боте — только Stars). В iOS-сборке нет ни цен, ни экрана, ни ссылок; о плате рассказывается вне приложения (бот, сайт, канал).
- Цена для первых подписчиков — 149 ₽ навсегда для оплативших по ней. Полная цена для новых включается командой `/plus stage full`. Своей группе подписка даётся подарком (`/plus gift`). Рассылка `/plusnews` отправляется только по кнопке администратора.
- Касса — ЮKassa, запасная — Robokassa. Без `PD_*` оплата закрыта.
- Звёзды Telegram: в `/plus` есть счёт XTR рядом со ссылкой на сайт. Цена — рубли × `STARS_MARKUP` (1.55) / `STARS_RUB` (1.8 ₽ за звезду; 0 — без Stars). Платёж пишется в `payments` с provider `stars`, `charge_id` нужен для возврата (`billing.stars_*`).
- Ручные выдачи — `plus_grant.py`, команда `/grant` (только администратор): продлить, безлимит (`plans.UNL`, `plus_unlimited`), `off` снимает только ручное. Журнал продлений — `plus_grants`. Своя группа с подарком получает тариф `sub`; без лимитов — только `config.is_starosta`.
- Приветствие «У тебя активна «Капибара+»» отправляет `plus_welcome.py`, один раз.
- Роадмап: `roadmap.py`, пункты в `roadmap.json`. Видят его все, кто поддержал проект любой суммой (оплаченный донат), и администратор — как благодарность, не как покупка. Бот: `/roadmap`; Mini App — строка под «Поддержать проект»; приложение — «Ещё» (`plus/roadmap.dart`); `GET /api/roadmap` (до доната — `locked` и ссылка на донат; iOS — `hidden`). Страница `/roadmap?k=` (`webapp/routes/roadmap_page.py`, стиль `site/roadmap.css`) показывает номер роадмапа (`edition`), итоги прошлого номера (`from`, `done`/`failed`/`now`) со ссылками на посты канала (`post`) и «Дальше». Новый номер — поднять `edition`, у обещанных пунктов — `from`. `roadmap.json` обновляется с выпусками: вышедшее переносится в `done`, новое добавляется простыми словами.

## Сайт

Статичная страница-презентация `/about` (`webapp/routes/site.py`, `webapp/static/site/`, свои шрифты в `site/fonts`).

- Живое приложение в рамке телефона — `/about/demo`. Это веб-сборка Flutter (`webapp/flutter`), первым скриптом идёт `site/demo-app.js`: сдвиг времени на запись, вход «demo» в своём localStorage в памяти (настоящий общий с `/app`, его не трогают), без service worker, ответы `/api/v1/…` из `site/demo.json` — записаны со стенда, чужих данных там нет. При изменении API `demo.json` перезаписывается. Прежний Mini App на демо-данных — `/about/demo/tg` (`site/demo.js` вместо SDK Telegram); он же показывается, пока сборки нет.
- Публичный поиск расписания: `/about/api/search` и `/about/api/target`, ограничение по IP (самый правый публичный адрес `X-Forwarded-For`) и общий `site_all`.
- Тёмная тема генерируется из светлой скриптом `tools/site_dark.py` (после правки `site.css` его нужно запустить, тест следит). Картинка превью ссылки `site/og.jpg` — `tools/site_og.py` со стенда.
- Кнопки сайта ведут на `?start=site`; в `/stats` такие пользователи помечены «с сайта».
- Страница «Было и стало» — `/history` (`site/history.html|css|js`): бот апреля 2026 (тексты из кода коммитов `53e40c0` и `c979db2`) рядом с экранами приложения (`site/history/*.jpg`, демо-данные), лента по датам. Тест — `test_site.test_history_page`.
- О способах пользоваться (Telegram, PWA `uiboshki.ru/app`, компьютер, своё приложение, входы VK и Яндекс) рассказывают во всех местах сразу: описание бота, `/start`, `/help`, `/app` (`bot.py`, `handlers/start.py`), WebApp «Ещё → Установить» и «Что нового» (`js/more.js`), сайт `/about`, README и README.en.md (меняются парами, `tests/test_readme.py`), пост в канал. Тест — `tests/test_platforms.py`.

## Канал бота

Посты лежат в `channel/posts/NN-имя/` (`post.html` в разметке Telegram и картинки). Публикует бот-администратор по кнопке старосты (`channel_posts.py`, `handlers/channel.py`).

- Пост всегда одно сообщение: картинки собираются в одну обложку (`cover_jpeg`), длинный текст идёт с обложкой над ним как превью ссылки `/chimg/<пост>.jpg` (`webapp/routes/channel.py`, нужен `WEBAPP_URL`).
- `/channel edit 1 4 6` правит выпущенные посты текстом из репозитория (обложка и комментарии остаются; править с аккаунта в Telegram посты с обложкой нельзя — снимается превью). `/channel redo` убирает выпущенное и выпускает заново; закреп бот ставит сам (имя папки содержит `pinned`: `00-pinned`, `13-sdo-guide-pinned`).
- Слово `news` в имени папки (`25-news-hello-pinned`) делает пост предназначенным для открытого канала (`LOGIN_CHANNEL`, `channel_posts.target`); остальные идут в канал разработки.
- Бот сам присылает старосте превью нового поста с кнопкой «В канал»; публикация только по кнопке.
- Если пост поправили вручную в Telegram, главным считается он: его текст переносится в `channel/posts/…/post.html`, и только потом применяются `/channel edit` или `redo`.
- Имя бота «Капибара МИРЭА» бот ставит сам (`bot.BOT_NAME`, `set_my_name`, только если отличается). Картинка описания (до `/start`) задаётся только через BotFather, `/setdescriptionpic`.

## Статистика и состояние

- Статистика (`stats.py`, `/stats` у старосты): таблица `events` (кто, что, когда, без содержимого). События собираются по пути запроса WebApp (`EVENT_PATHS`, в `get_current_user`) и по сообщениям боту (`StatsMiddleware`). Картинка рисуется Pillow, шрифт DejaVu лежит в `assets/fonts`. Под картинкой кнопка «Кто пользуется» (`stats.people`): имя (ссылкой на профиль), ник, последний заход, число дней с заходами, чем пользуется. События старше 180 дней удаляются.
- Состояние бота (`health.py`, `/status` у старосты): отметки «когда и чем кончилось» для синка СДО, проверки куки и бэкапа лежат в `settings` (`health:*`). Ошибки и предупреждения из логов за сутки по разделам считает `health.ErrorCounter` (в памяти, подключается в `bot.py`). При всплеске (не меньше 5 ошибок за час) бот сам пишет старосте (`health.alert_errors`, проверка раз в 15 минут, сообщение не чаще раза в 3 часа). `/status` также показывает прогресс индекса, траты «Подумать ещё», предупреждения о ключах.
- Бэкап: ночная копия базы уходит старосте в 04:40 (`backup.py`), есть команда `/backup`. Восстановление — `/restore` (`backup.inspect_backup`, `apply_backup`). При заданных `BACKUP_S3_*` копия идёт в S3 (`s3_store.py`), а не в Telegram.
- Проверка сети с сервера — `/netcheck`.

## Код по модулям

- База — пакет `database/`: `schema`, `users`, `deadlines`, `files`, `sdo`, `schedule`, `social`, `homework` (доска ДЗ, `is_editor`), `settings`, `service`. Снаружи импорт `from database import …`.
- Подключение — только `database._conn.connect()`; путь к базе — `database._conn.DATABASE_PATH`, читается при вызове. Тесты подменяют `database.DATABASE_PATH`; функции, читающие модуль, подменяются в подмодуле (например `database.deadlines.today_msk`).
- Файлы в боте — `handlers/files.py` плюс `files_upload`, `files_sdo`, `files_admin`. Объявления — `handlers/announce.py` плюс `homework`, `group_tools`. Подмодули подключаются к роутеру основного модуля в прежнем порядке (в aiogram сначала срабатывают обработчики самого роутера, потом вложенных).
- Настройки в виде JSON (уведомления, цели, выпущенные посты) пишутся под замком `locks.lock(...)`.
- Любая команда посреди FSM-диалога сбрасывает его (`MenuInterruptMiddleware`), есть общий `/cancel`.
- Фоновые задачи запускаются через `kapibara.core.tasks.spawn`, а не голым `asyncio.create_task`.
- Новые исходящие запросы за границу идут через `net.client()`, не через `httpx.AsyncClient`; `Bot(...)` создаётся с `session=net.tg_session()`.
- Храповик `tools/ratchet.py`: широкие `except`, молчаливые `pass`, модули в клубке импортов, файлы в корне и замечания Ruff из `RUFF_DEBT` могут только уменьшаться. Ошибки типов проверяет `python -m mypy` (`mypy_errors`, в ядре `mypy_core` равно 0). Если показатель вырос, CI красный; если уменьшился — `python tools/ratchet.py --update` и коммит `tools/ratchet.json`. Семейства B, ASYNC, SIM, C4, PERF, UP достигли нуля и включены в `select` в `ruff.toml`.
- Версии выпускаются пачками. Обычный PR версию не ставит, а кладёт заметку `changelog.d/next/<ветка>.md` (`python tools/changelog.py note`, текст пунктами из stdin). Релизный PR собирает заметки командой `python tools/changelog.py release X.Y.Z Имя` в `changelog.d/X.Y.Z.md`; `pending` показывает ожидающие заметки, `free` и `figures` — свободные имена (пул `FIGURES`, `OWNER_NAMES`, `SONG_WORDS`). `changelog.py pr-check` в CI не пускает версию в обычный PR. После мержа записи в `CHANGELOG.md` переносит GitHub Action `changelog.yml` (`collect`).
- Ветку `deploy` двигает `deploy.yml` только после зелёного CI на main. `/api/meta` → `build` и шапка `/status` показывают, какая сборка работает.

## Тесты

Запуск: `python -m pytest -q` (700+ тестов, без сети) и `ruff check .` (тоже в CI).

- `tests/conftest.py`: фикстура `db` (чистая SQLite с миграциями), заглушки сети для расписания и календаря СДО, семестр зафиксирован на 26.09.2026. В тестах согласие дано (`conftest._consent_given`); настоящая проверка помечается `consent_real`.
- Хендлеры проверяются через настоящий `Dispatcher.feed_update` с фейковой сессией бота.
- `tests/test_webapp_static.py` проверяет фронт: `node --check`, id, onclick, подключение файлов.
- Дымовой тест WebApp в Chromium — `tests/test_webapp_smoke_browser.py`.
- Названия и правила разбора (файлы, дедлайны) проверяются на настоящих данных группы: прогон, сравнение «было → стало» до применения.
- Каждый баг получает тест.

## Ограничения

- Бот рассчитан на одну основную группу. Для другой группы со своим СДО нужна отдельная копия: свой бот, хостинг, кука студента и ключ Gemini. Имя группы, бота и направление задают переменные `GROUP_NAME`, `BOT_USERNAME`, `GROUP_PROGRAM` (по умолчанию УИБО-03-24, uiboshkibot, «Бизнес-информатика»), календарь — `ICAL_URL`.
- Поиск по смыслу зависит от бесплатных эмбеддингов Gemini; первый индекс собирается фоном за ночь, пока векторов нет, гибрид работает только по словам.
- Gemini и DeepSeek работают на бесплатных лимитах, бывают сбои.
- Пульс МИРЭА недоступен без отдельного входа, посещения восстанавливаются приближённо из баллов.
