# Ключ подписи Android (для RuStore)

Каждый APK подписан ключом. По ключу телефон узнаёт, что обновление — от того же
автора. **Один раз сделал ключ — им подписываются все версии навсегда.**

> **Главное.** Потеряешь ключ или пароль — новую версию в RuStore выпустить будет нельзя:
> придётся заводить новое приложение, а всем — удалять старое и ставить заново.
> Храни файл `kapibara-upload.jks` и пароль **в двух местах** (например, флешка +
> облако с паролем, или менеджер паролей). В чат, в репозиторий и людям — никогда.

Всё ниже — на Windows, в PowerShell. Займёт минут 15.

## 1. Где взять `keytool`

`keytool` — программа из Java. Есть два варианта:

- **Уже стоит Android Studio** — `keytool` лежит тут:
  `C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe`
- **Нет Android Studio** — поставь Java: https://adoptium.net → «Temurin 21 (LTS)» →
  Windows x64 → `.msi`. При установке отметь пункт **«Set JAVA_HOME»** и
  **«Add to PATH»**. Потом закрой и снова открой PowerShell.

Проверка (в PowerShell):

```powershell
keytool -help
```

Если пишет «не является именем командлета» — значит, PATH не подхватился. Тогда
вместо `keytool` пиши полный путь в кавычках с `&` впереди, например:

```powershell
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -help
```

## 2. Сделать ключ

Создай папку для ключа и перейди в неё:

```powershell
mkdir $HOME\kapibara-keys
cd $HOME\kapibara-keys
```

Сделай ключ (одна строка):

```powershell
keytool -genkeypair -v -keystore kapibara-upload.jks -storetype PKCS12 -keyalg RSA -keysize 4096 -validity 36500 -alias kapibara
```

Он спросит:

1. **Пароль хранилища** (два раза) — придумай длинный, от 12 знаков, только латиница и
   цифры (без кавычек и пробелов). Запиши его рядом с файлом ключа (в менеджер паролей).
2. Имя и фамилия, подразделение, организация, город, область, код страны — можно
   ответить как есть (`Nikita ...`, Enter, Enter, `Moscow`, Enter, `RU`). Это видно
   только в свойствах подписи.
3. «Is CN=… correct?» — напиши `yes`.

Пароль ключа отдельно он не спросит: в формате PKCS12 он такой же, как у хранилища.
Сборка в GitHub так и рассчитывает — один пароль на всё.

Появится файл `kapibara-upload.jks`. **Сейчас же скопируй его во второе место.**

Посмотреть отпечаток ключа (пригодится, если RuStore спросит):

```powershell
keytool -list -v -keystore kapibara-upload.jks -alias kapibara
```

Строка `SHA256:` — это он.

## 3. Превратить ключ в текст (base64)

GitHub хранит секреты текстом. Эта команда кладёт ключ текстом сразу в буфер обмена:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("$HOME\kapibara-keys\kapibara-upload.jks")) | Set-Clipboard
```

Ничего не печатает — так и надо, текст уже в буфере.

## 4. Положить три секрета в GitHub

Открой репозиторий на GitHub → **Settings** → слева **Secrets and variables** →
**Actions** → зелёная кнопка **New repository secret**. Три раза:

| Name                   | Secret (что вставить)                                   |
|------------------------|---------------------------------------------------------|
| `ANDROID_KEYSTORE`     | Ctrl+V — текст из шага 3 (длинная строка букв)           |
| `ANDROID_KEY_ALIAS`    | `kapibara`                                              |
| `ANDROID_KEY_PASSWORD` | пароль из шага 2                                        |

Каждый раз — **Add secret**. Посмотреть значение потом нельзя, только заменить — это нормально.

## 5. Собрать подписанный APK

1. GitHub → вкладка **Actions** → слева **«Сборка приложения»** → справа **Run workflow**.
2. Поле **«Версия для магазинов»** — например `1.0.0` (каждый новый выпуск в магазин —
   больше прошлого: `1.0.1`, `1.1.0`…). Галочку TestFlight для Android не трогай.
3. **Run workflow**, подожди ~10 минут, открой запуск.
4. Внизу страницы, в **Summary**, — блок «Android»: там `versionName`, `versionCode`,
   разрешения и `certificate DN: CN=…` — твоё имя, **не** `CN=Android Debug`.
   Если видишь «отладочным ключом» — секреты не подхватились, проверь имена.
5. **Artifacts** → `kapibara-android-<номер>` → скачается zip, в нём
   `kapibara-<номер>.apk` (его — в RuStore) и `.aab` (запас на будущее, см. ниже).

Номер сборки (`versionCode`) растёт сам — это номер запуска. Ничего вписывать не нужно.

## Важно

- **Старый APK на телефоне** (с отладочной подписью, из прошлых сборок) обновить
  магазинной версией нельзя — подписи разные. Его нужно один раз удалить, потом
  поставить из RuStore.
- **Почему APK, а не AAB.** RuStore принимает оба. Но для AAB нужно отдать RuStore
  сам ключ подписи (зашифрованным, через их программу PEPK) и сделать второй ключ
  «загрузки». С APK ключ остаётся только у тебя, а шагов меньше. AAB всё равно
  собирается — пригодится для Google Play, если он когда-нибудь будет.
- Ключ и пароль — тоже секреты: не писать их в чат с ассистентом, не коммитить.
