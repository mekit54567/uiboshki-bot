# 0002. Слои и направление импортов

Статус: принято (02.11.2026)

## Контекст
35 корневых модулей сцеплены взаимными импортами в один клубок, 20 пар
импортируют друг друга напрямую. База зовёт бизнес-логику
(`database/users.py` → `privacy`), планировщик берёт погоду из
Telegram-хендлера (`scheduler.py` → `handlers.weather`). Код не падает только
потому, что ~800 импортов спрятаны внутрь функций.

## Решение
Импорт идёт только сверху вниз:

    bot.py (сборка)          знает про всё
    bot/  web/  jobs/  ops/  интерфейсы; друг друга не импортируют
    features/                логика продукта; про Telegram и HTTP не знает
    database/                только запросы к базе, без бизнес-правил
    core/                    ничего своего не импортирует

Правило проверяет CI (import-linter, `.importlinter`), а не память того,
кто пишет код. Проверяются прямые импорты: `bot | jobs → ops → features →
core`, база — только `core`. 25 нарушений на 02.11 — в `ignore_imports`, этот
список только сокращается ([0006](0006-ratchet.md)).

## Почему не иначе
Взаимные импорты внутри функций «работают», но прячут зависимости: правка
оплаты может сломать бэкап через цепочку из десятка модулей, и это видно
только в проде.

## Последствия
Чтобы нижний слой сообщил что-то верхнему, нужен параметр или колбэк, а не
импорт. Например, `features/` возвращает текст, а отправляет его `bot/`.
