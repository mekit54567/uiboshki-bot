# 0003. Перенос модулей через переадресацию `sys.modules`

Статус: принято (02.11.2026)

## Контекст
Сервер обновляется сам после каждого мержа. В тестах ~780 подмен вида
`monkeypatch.setattr(sdo_grades, "fetch", ...)`; модули держат состояние
(кэши, замки, лимиты частоты).

## Решение
На старом месте остаётся файл из двух строк, отдающий **тот же объект модуля**:

    # sdo_grades.py — переехал в kapibara/features/sdo/grades.py
    import sys, kapibara.features.sdo.grades as _m
    sys.modules[__name__] = _m

PR с переносом не меняет ни строки логики (git видит переименование на
100%), в нём есть тест «старое и новое имя — один модуль». Когда переедут
все темы, один PR скриптом меняет импорты и удаляет переадресации.

## Почему не иначе
`from new import *` создаёт вторую копию пространства имён: тест подменял
бы одну, код работал бы с другой (тест пошёл бы в настоящую сеть), а в проде
разъехались бы кэши и замки.

## Последствия
Пути к файлам данных (шрифты, roadmap, посты канала) считаются от корня
проекта, имена логгеров для `/status` задаются явно — перенос их не трогает.
