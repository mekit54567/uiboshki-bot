# 0006. Храповик вместо «починить всё разом»

Статус: принято (02.11.2026)

## Контекст
Плохих мест много, а прод обновляется после каждого мержа. Большой
рефакторинг одним PR невозможно проверить и опасно выкатывать.

## Решение
`tools/ratchet.py` в CI считает широкие `except`, молчаливые `pass`, модули
в клубке импортов и файлы в корне. Потолок — в `tools/ratchet.json`. Цифра
выше потолка — CI красный. Цифра ниже — тоже красный, пока потолок не опущен
(`python tools/ratchet.py --update`), иначе улучшение можно молча откатить.

## Почему не иначе
- Включить строгий линтер сразу — сотни ошибок, CI красный неделями.
- Не проверять вовсе — новые плохие места появляются быстрее, чем чинятся.

## Последствия
Новый код сразу пишется чисто, старый чистится по ходу. Каждый PR, который
что-то улучшил, опускает потолок в том же PR.

03.11: в храповик добавлена проверка типов mypy (`mypy.ini`): `mypy_errors` —
по всему серверу, только вниз; `mypy_core` — в ядре (`kapibara/core`, `bot`,
`jobs`, `database`, `bot.py`), там уже ноль. Дальше — по разделу за PR.

12.11: `mypy_errors` = 0 по всему серверу. Ошибки, которые прятали в коде
`Optional` от aiogram (сообщение под кнопкой бывает недоступно, у события нет
бота или текста), убраны через узкие геттеры `kapibara/bot/tg.py`: устаревшая
кнопка — `StaleMessage`, бот отвечает «вызови команду заново», а не падает.
