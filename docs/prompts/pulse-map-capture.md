# Снимок карты Пульса МИРЭА — промпт для Claude Code с расширением Chrome

Как запустить (Никите):
1. На компьютере: Chrome с расширением Claude in Chrome, Claude Code в любой
   пустой папке, например `Downloads\pulse-map`.
2. В Chrome самому войти в https://pulse.mirea.ru (паролем или по QR) —
   Claude вход не делает и пароль не видит.
3. Вставить в Claude Code всё, что ниже линии, целиком.
4. В конце Claude соберёт `pulse-map-<дата>.zip` — прислать его Claude в чат (для PR #219).

---

Задача: снять карту корпусов из Пульса РТУ МИРЭА (https://pulse.mirea.ru/services/maps)
так, как её получает сам сайт, и сохранить данные карты в файлы. Я уже вошёл в
Пульс в этом Chrome своим аккаунтом. Это разовый снимок для моего приложения
(в приложении будет подпись «Пульс РТУ МИРЭА»).

## Правила
- Репозиторий бота не клонируй и код не пиши: задача — только снять карту и
  собрать архив (небольшие одноразовые скрипты для выгрузки и проверки файлов — можно).
- Работай только на pulse.mirea.ru, только в разделе карты (`/services/maps`).
  Другие разделы Пульса (оценки, посещения, профиль, сообщения) не открывай.
- Пароли, коды, куки, токены не вводи и не сохраняй. В итоговых файлах — только
  данные карты: никаких заголовков запросов, куки, `authorization`, id сессии,
  моего имени, почты, номера студенческого.
- Ничего не меняй на сайте (никаких отправок форм, правок, «сообщить об ошибке»).
- Не нагружай сайт: каждый корпус открыть один раз, пауза между запросами
  2–3 секунды, никаких переборов id.

## Что нужно получить
Для каждого корпуса, который есть на карте (ожидаю 4: В-78, В-86, С-20, МП-1;
если Пульс показывает другие — снимай все, что есть в списке корпусов):
1. Ответ запроса `GetCampus` (gRPC-Web; может называться по-другому — ищи
   запрос, после которого на карте появляются этажи и аудитории). Тело ответа —
   как есть, байты без изменений.
2. Всё, что сайт догружает для этажей: SVG или картинки планов этажей, если они
   идут отдельными запросами.
3. Данные для маршрутов. Проверь, где они: (а) уже внутри ответа GetCampus (граф:
   точки и переходы, лестницы, лифты) или (б) отдельный запрос при построении
   маршрута. Чтобы это увидеть, в одном корпусе построй на карте маршрут между
   двумя аудиториями (например, А-223 → Г-412 в В-78) и сохрани все запросы,
   которые при этом ушли. Если маршрут считается на сервере — сохрани и запрос,
   и ответ этого маршрута (тело запроса тоже: в нём только id точек).
4. Описание формата: файлы JavaScript сайта, где описаны сообщения карты (ищи в
   загруженных скриптах строки `GetCampus`, `Campus`, `Floor`, `Room`, `Graph`,
   `Node`, `Edge`). Сохрани эти файлы целиком — по ним мы прочитаем двоичный
   ответ по именам полей. Это открытые файлы сайта, без личных данных.

## Как снять (основной путь)
1. Открой https://pulse.mirea.ru/services/maps.
2. До выбора корпуса поставь в странице перехват ответов (через выполнение
   JavaScript во вкладке): обёртка над `window.fetch` и `XMLHttpRequest`,
   которая для запросов на pulse.mirea.ru, связанных с картой (по URL: `Campus`,
   `Map`, `Floor`, `Route`, `.svg`), сохраняет в `window.__mapCap` массив
   записей `{url, method, status, contentType, requestBodyBase64, responseBodyBase64, at}`.
   Заголовки запросов и ответов НЕ сохраняй. Ответ бери через `response.clone()`.
3. По очереди выбери в интерфейсе каждый корпус (без перезагрузки страницы, иначе
   перехват пропадёт; если корпус открывается только перезагрузкой — поставь
   перехват заново после неё), пролистай все этажи, построй один маршрут (п. 3).
4. Выгрузи `window.__mapCap`: сделай в странице `Blob` с JSON и скачай файлом
   `pulse-map-capture.json` (через временную ссылку `<a download>`), он попадёт в
   «Загрузки». Если файл большой (больше 50 МБ) — по файлу на корпус.

Запасной путь, если перехват не работает: попроси меня открыть DevTools →
Network, включить «Preserve log», пройти корпуса, нажать правой кнопкой →
«Save all as HAR with content». HAR содержит куки — его не копируй никуда,
только прочитай локально скриптом, вынь нужные тела ответов и сразу удали HAR.

## Куда и в каком виде положить
Папка `pulse-map/` в текущей папке:
- `raw/<корпус>-GetCampus.bin` — тело ответа GetCampus байтами (если ответ
  пришёл как `application/grpc-web-text`, сначала раскодируй base64; в имени
  корпус латиницей: `v-78`, `v-86`, `s-20`, `mp-1`).
- `raw/<корпус>-floor-<этаж>.svg` (или .png/.webp) — планы этажей, если они
  отдельными запросами.
- `raw/route-request.bin`, `raw/route-response.bin` — если маршрут считается на
  сервере.
- `js/` — файлы скриптов сайта с описанием сообщений карты (п. 4).
- `index.json` — список: для каждого корпуса название, id корпуса из адреса
  (`?campus=…`), какие файлы к нему относятся, размер и sha256 каждого файла,
  сколько этажей видно в интерфейсе, URL и gRPC-метод каждого сохранённого запроса
  (без заголовков).
- `README.md` — дата и время снимка, как снимал, где оказались данные маршрутов
  (в GetCampus или отдельным запросом), что не получилось.

## Проверь, что снимок полный
- Корпусов столько же, сколько в списке корпусов на карте Пульса.
- У каждого корпуса ответ GetCampus не пустой (сотни килобайт и больше).
- В двоичном ответе находятся названия аудиторий: поиск строк в файле (UTF-8)
  находит, например, «А-223» и «Г-412» в В-78; аудитории есть на каждом этаже,
  который видно в интерфейсе.
- Данные маршрутов есть: либо в GetCampus найдены много повторяющихся записей
  точек/переходов (их тысячи), либо сохранён ответ маршрута.
- Секретов нет: поиск по всем файлам `pulse-map/` (без учёта регистра) не находит
  `cookie`, `authorization`, `bearer`, `session`, `token`, `password`, моё имя,
  фамилию, почту. Если что-то нашлось в `js/` как часть кода сайта (например,
  слово `token` в названии функции) — это нормально, опиши в README; в `raw/`
  такого быть не должно.
- Файлы из «Загрузок» и HAR (если был) после переноса удали.
