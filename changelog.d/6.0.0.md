### v6.0.0 «Бакст»
- Публичный запуск: Капибара выходит из «для своей группы» к студентам МИРЭА. Главное — новый дизайн «Тетрадь» (и «Ночная тетрадь») как основной вид везде: приложение, браузер и Mini App. Вместе с ним — рейтинг групп, лента уведомлений с тихими часами и новые скриншоты в сторах.
- Архитектурные решения записаны в `docs/adr/` (раскладка `kapibara/`,
  слои, перенос модулей, ошибки, выкладка, храповик) и шаблон PR с
  чеклистом: тест, заметка, безопасная схема, узкие except.
- Расписание: ошибки разделены по ADR 0004. Если зеркало не ответило, в лог пишется одна строка; если сломался разбор, пишется полный след ошибки, чтобы его было видно в /status.
- Расписание дня из инлайна для чужой группы, которое не загрузилось, теперь отвечает строкой «не удалось», а не падает.
- СДО: одна граница ошибок на все экраны (вход протух → «подключи заново», СДО не ответил → «не отвечает», баг → в /status с полным следом). Необязательные шаги (история баллов, отметка «сдал», посещения) больше не прячут баги в одну строку лога.
- Баг в разборе журнала больше не выдаётся за «курс не найден».
- Решалка в боте: одна граница ошибок на все ответы ИИ. Человек видит «ИИ сейчас не ответил» вместо текста исключения, а баг попадает в /status с полным следом.
- Поиск по лекциям: узкие ошибки при загрузке векторов и скачивании файла.
- Бэкап, /status, статистика, /netcheck: узкие ошибки вместо «любой» (Telegram и сеть, база, файлы). Временный файл проверки копии при /restore убирается в finally.
- Веб-маршруты расписания и файлов: узкие ошибки (расписание не загрузилось, Telegram не отдал файл, страница PDF не нарисовалась) вместо «любой».
- Широкие except: 191 → 120. Рассылки по людям, сообщения старосте и шаги после синка идут через одну границу kapibara.core.errors.aside: сеть и отказ Telegram (бот заблокирован) — одной строкой, настоящий баг — с traceback (раньше баг в рассылке был видел только строкой и терялся).
- Широкие except: 120 → 96. «Не вышло — взять запасное значение» — через aside; правка сообщений и рассылки в боте ловят только отказ Telegram, запросы к базе — только ошибки SQLite: настоящий баг больше не прячется за запасным ответом.
- Широкие «except Exception» 96 → 48: сеть, база и отказы Telegram ловятся своими типами, а ошибка в нашем коде больше не прячется под «сервис не ответил» (например, проверка канала при входе, синк СДО, оплата, пуши)

  проверяли не то, что запускаем). Новая проверка `tools/check_imports.py`:
