# УИБО-бот — памятка для ИИ-ассистента

Этот файл нужен, чтобы в новом чате сразу было понятно, что это за проект, как
устроен и как с ним работать. История версий — `CHANGELOG.md`, план — `PLAN.md`.

## Что это
Telegram-бот и Mini App (WebApp) группы **УИБО-03-24, РТУ МИРЭА**:
расписание, дедлайны из СДО (Moodle), файлы курсов по предметам и типам, ИИ-чат
и решалка, которые опираются на лекции группы, поиск расписания любого
преподавателя, группы или аудитории МИРЭА. Бот: `@UiboshkiBot`. Владелец и
староста — Никита (в Telegram @Partykq). Общается по-русски, коротко и
неформально, часто пишет с телефона.

## Правила работы (от владельца, обязательны)
- Каждое изменение — отдельная ветка, потом PR в `main`, затем мерж **обычным
  merge commit, не squash**. Мержит владелец (сам ассистент не мержит).
- Коммиты на русском. `git add` — только конкретных файлов, **никогда `-A`**.
- На каждый баг — тест. CI (GitHub Actions) должен быть зелёным до мержа.
- **У каждого коммита своя версия в `CHANGELOG.md`**: `эпоха.фича.фикс`
  (сейчас эпоха 2), кодовое имя — одно слово (зверь, птица или предмет).
  Теги ставит владелец сам через GitHub → Releases, из облака их не пушим.
- **Никогда не цитировать тексты песен** (раньше из них брали имена версий).
- **Никаких подписей ИИ** в коммитах и PR (Co-Authored-By, ссылки на сессию,
  «Generated with…»): владелец просил. Упоминание есть одной строкой в README.
- Секреты (токены, куки, ключи) — только в переменных окружения Railway, в
  чат их не просить и значения нигде не повторять.
- Живой тест в Telegram Web — только вход по QR, без номера телефона, кодов из
  SMS и облачного пароля. Работать только в чате с ботом. В конце напомнить
  владельцу завершить веб-сеанс (Настройки → Устройства).
- Бюджет владельца ограничен: делать по делу, без лишних скриншотов и прогонов.

## Деплой
`mekit54567/uiboshki-bot` (main) → форк **`Deployac/uiboshki-bot`** → Railway
(деплой из форка). После мержа владелец жмёт в форке **Sync fork → Update
branch** (в приложении GitHub на iOS такой кнопки нет — только в браузере).
WebApp: `https://uiboshki-bot-production.up.railway.app`, живёт в процессе
бота (FastAPI + uvicorn, `webapp/server.py`, `bot.start_webapp`).

Переменные окружения (см. `config.py`): `BOT_TOKEN`, `STAROSTA_ID`,
`GROUP_CHAT_ID` (пока не задан — лента «Подслушано» выключена), `ICAL_URL`
(календарь группы, по умолчанию УИБО-03-24 = группа 4928 на зеркале),
`DATABASE_PATH`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `DEEPSEEK_API_KEY`
(необязательно), `WEBAPP_URL`, `PORT`, `SDO_SESSION_COOKIE`,
`SDO_SYNC_INTERVAL_HOURS` (6), `SDO_KEEP_COURSES` (по умолчанию «Учебный отдел»).

## Как устроено (главное)
- **Расписание МИРЭА.** Официальный API `schedule-of.mirea.ru` из-за рубежа не
  отвечает (сервер Railway в США). Используется зеркало
  `english.mirea.ru/schedule/api/ical/{тип}/{id}` (1 — группа, 2 — преподаватель,
  3 — аудитория). Поиска на зеркале нет, поэтому `schedule_index.py` один раз
  обходит id и берёт имена из `X-WR-CALNAME` (первый килобайт, Range), хранит в
  SQLite, обновляет раз в месяц. Поэтому поиск работает и с VPN.
  Разбор ical — `schedule_parser.py` (`lessons_for_date`, `week_overview`,
  `target_weeks`, номер недели из событий «N неделя»).
- **СДО (Moodle, online-edu.mirea.ru)** — по куке `MoodleSession` владельца.
  Из облачной сессии разработки СДО недоступен, с Railway — доступен.
  Сессия Moodle гаснет через 8 ч без запросов; синк раз в 6 ч держит её живой.
  - Дедлайны (`sdo_parser.py`): AJAX `core_calendar_get_calendar_monthly_view`
    на 5 месяцев (sesskey со страницы `/my/`), запасной путь — «Предстоящие
    события». Типы сроков — `DEADLINE_EVENTS`. Курсы не этого семестра
    отсекаются по метке `[II.25-26]` в названии и по отсутствию в расписании
    группы (`not_this_semester`, исключения — `KEEP_COURSES`).
    Правка дедлайна вручную (`manual_edit`) защищает его от перезаписи синком.
  - Файлы (`sdo_files.py`, команда `/sdofiles`): курсы — AJAX «Мои курсы»,
    материалы — `course/resources.php`, папки раскрываются. Сначала пробный
    прогон, потом выгрузка кнопкой: файл отправляется старосте, бот берёт
    `file_id` и удаляет сообщение. `files.source` — защита от дублей,
    `files_skipped` — удалённое не вернётся. Выгружено 596 файлов, 535 с текстом.
- **Файлы** (`file_categories.py`): тип по названию (лекции, практики и лабы,
  КР и тесты, методички, экзамен, другое), естественная сортировка номеров.
  Удалять может только староста (`/delfile`, кнопки в WebApp).
- **ИИ**: Gemini — основной (`gemini_solver.py`), DeepSeek — опционально
  (`ai_solver.py`). Лекции под вопрос подбирает `lecture_picker.py` (по словам с
  учётом опечаток, до ~200 тыс. символов; без выбранного предмета — по всем
  предметам при совпадении). Если с лекциями ответ не прошёл — чат WebApp
  отвечает без них и пишет причину. Математика в ответах — `utils.pretty_math`,
  Markdown модели → HTML Telegram — `md_to_tg_html_chunks`.
- **WebApp**: авторизация по `initData` (HMAC, `webapp/auth.py`). Фронт —
  `webapp/static/index.html` + `app.css` + `js/{core,home,deadlines,files,
  search,chat,main}.js` (классические скрипты, общая глобальная область,
  порядок важен). `/` отдаёт index со ссылками `?v=<хэш>` против кэша Telegram.
- **Прочее**: длинные сообщения режутся на части (`long_messages.py`,
  middleware сессии бота); ночной бэкап базы старосте в 04:40 и `/backup`
  (`backup.py`); задачи по расписанию — `scheduler.py` (APScheduler).

## Тесты
`python -m pytest -q` (≈260 тестов, без сети). `tests/conftest.py`: фикстура
`db` (чистая SQLite с миграциями), заглушки сети для расписания и календаря
СДО, семестр зафиксирован на 26.09.2026. Хендлеры проверяются через настоящий
`Dispatcher.feed_update` с фейковой сессией бота. `tests/test_webapp_static.py`
проверяет фронт: `node --check`, id, onclick, подключение файлов.

## Известные ограничения и что дальше
- Бот рассчитан на одну группу. Для общего чата разных групп нужны: выбор своей
  группы на главной, закрытие дедлайнов, файлов и ИИ для не-участников чата
  группы (проверка через `GROUP_CHAT_ID`), лимит ИИ для чужих. Для другой группы
  со своим СДО — отдельная копия (свой бот, Railway, кука студента, свой ключ
  Gemini). Перед этим вынести в переменные `GROUP_NAME` и `BOT_USERNAME`
  (сейчас «УИБО-03-24» и `uiboshkibot` местами зашиты в код).
- Восстановление из бэкапа ручное и на проде не проверялось.
- Подбор лекций — по словам, не по смыслу (синонимы не находит).
- Gemini и DeepSeek на бесплатных лимитах: бывают сбои.
