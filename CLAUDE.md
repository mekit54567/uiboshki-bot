# CLAUDE.md

Памятка для ИИ-агента, который работает в этом репозитории. Людям удобнее
начать с [README](README.md) и [CONTRIBUTING](CONTRIBUTING.md).

## Проект

«Капибара» — неофициальное учебное приложение для студентов РТУ МИРЭА:
расписание, дедлайны и баллы из СДО (Moodle), сдача работ, файлы курсов,
ИИ-ответы по лекциям группы. Клиенты: Telegram-бот [@UiboshkiBot](https://t.me/UiboshkiBot)
с Mini App, PWA (`uiboshki.ru/app`), приложение на Flutter для iOS и Android.
Все ходят в одно API `/api/v1` на FastAPI. Сервер — один процесс (бот + API),
SQLite, Docker на VPS.

## Команды

```bash
python -m pytest -q          # тесты сервера, без сети
ruff check .                 # линтер
python tools/ratchet.py      # храповик качества
python tools/changelog.py note  # заметка к PR (пункты из stdin)
python tools/api_snapshot.py # обновить снимок API после нового пути
cd app && flutter test       # тесты приложения (SDK в облаке: /home/user/sdk/flutter)
```

## Карта кода

| Где | Что |
|---|---|
| `kapibara/` | сервер: `core/`, `features/<раздел>/`, `jobs/`, `bot/`, `ops/` |
| `bot.py` | точка входа |
| `database/`, `handlers/`, `webapp/` | прежняя раскладка, код переезжает в `kapibara/` ([ADR 0001](docs/adr/0001-package-layout.md)) |
| `webapp/static/` | Mini App (`index.html` + `js/`), PWA на HTML (`app-html/`), сайт (`site/`) |
| `app/` | приложение на Flutter |
| `tests/`, `tools/`, `deploy/`, `channel/`, `design/` | тесты, скрипты, сервер, посты, дизайн-токены |

Модули в документации местами названы по-старому (`sdo_parser.py`,
`scheduler.py`…). Где каждый сейчас — таблица `MOVED` в
`tests/test_moved_modules.py`.

## Правила

1. Каждое изменение — своя ветка и PR в `main`. Мерж обычным merge commit,
   мержит владелец, агент не мержит.
2. Коммиты на русском. `git add` — только конкретных файлов, никогда `-A`.
3. Никаких подписей ИИ в коммитах и PR: без Co-Authored-By, ссылок на сессию,
   «Generated with…».
4. На каждый баг — тест. CI зелёный до мержа.
5. Храповик только вниз: стало меньше — `python tools/ratchet.py --update` и
   закоммитить `tools/ratchet.json`. Фоновые задачи — `kapibara.core.tasks.spawn`.
6. Обычный PR версию не ставит, только заметку `changelog.d/next/<ветка>.md`.
   Версию и кодовое имя ставит релизный PR раз в ~10 PR; номер даёт
   координатор проекта. В `CHANGELOG.md` новые записи руками не добавлять.
7. PR открывать не черновиком. Сразу подписаться на него; конфликт — влить
   `origin/main` обычным merge и починить самому. Перед «можно мержить» —
   `git merge-tree --write-tree HEAD origin/main` без конфликтов.
8. В PR, который уже ждёт мержа, не пушить: новые правки — новой веткой.
9. Секреты (токены, куки, ключи, код демо-входа) — только в переменных
   окружения сервера. Не просить их в чате и не повторять значения.
10. Изменения настроек (хостинг, переменные, BotFather, DNS, GitHub) — сначала
    показать, что и зачем; делает владелец.
11. Большую новую работу — спросить, начинать ли. Доработки — в ту же ветку.
12. Дизайн — сначала варианты картинками со стенда, делать выбранное. Пачками
    по пять пунктов ([docs/design-review.md](docs/design-review.md)), к
    каждому — скрин работающего кода. Новый вид — только под
    `AppStyle.fresh` / `Theme.fresh`, прежний не трогать.
13. Правила разбора названий (файлы, дедлайны) проверять на настоящих данных
    группы и показывать «было → стало» до применения.
14. Всё — с расчётом на любую группу и своё приложение: JSON без HTML, группа
    из профиля, рассылки через `delivery.deliver`, API в `/api/v1`.
15. Новый способ пользоваться — рассказать везде сразу (см. CONTRIBUTING,
    `tests/test_platforms.py`). Меняешь README — поправь оба языка.
16. Большие пачки можно делать параллельно агентами, каждый в своём worktree
    от `origin/main`; агенты не трогают CHANGELOG, `changelog.d/`, PLAN и
    CLAUDE и не пушат, ведущий собирает их коммиты в одну ветку.
17. После большой задачи — коротко обновить «Где мы сейчас» в PLAN.md.
    Новое правило работы — сразу сюда.
